## 2. 本輪範圍

交付一個可由 Node.js 呼叫的公式核心、後端 PDF 共用的驗證及求值流程、計算欄位編輯介面，以及 MCP 能力目錄與驗證工具。獨立示範程式需要接上相同的後端流程，才能驗證前端所見結果與正式輸出一致。此處的後端不綁定 NestJS，也不引入 Haneinfo 的認證、資料庫或範本服務。

Excel／Word 匯出、跨資料庫查詢、視覺化公式組合器、自訂函式、多層子報表、交叉表、復原／重做及完整獨立 AI 產品留在後續。MCP 公式發現與驗證則屬於本輪。

## 3. 共用公式註冊表

每個內建函式的實際執行器與能力規格放在同一個登錄項目。設計器說明、MCP 回傳及測試案例從該項目取得，避免手動維護另一份支援清單。

每個登錄項目包含：

- 穩定名稱、類別、別名與說明。
- 簽章、具名參數、參數型別、選填／預設值、可變參數及回傳型別。
- scalar／aggregate 類型、可使用的計算範圍、空集合及空值行為。
- 是否短路求值、是否依賴執行時間、可能的錯誤代碼。
- 可執行的正常與邊界範例、引擎／目錄版本。

完整 v1 建議清單如下。這是實作目標；尚未完成的函式不得在實際 MCP 目錄中宣告為可用。

| 類別 | 建議內建函式 | 用途與主要規則 |
| --- | --- | --- |
| 數值 | `ABS`、`ROUND`、`ROUNDUP`、`ROUNDDOWN`、`MOD` | 絕對值、指定小數位與餘數；明確說明負數與取整規則。 |
| 條件與空值 | `IF`、`AND`、`OR`、`NOT`、`COALESCE`、`ISNULL` | 條件判斷、布林組合與明確預設值。 |
| 彙總 | `SUM`、`COUNT`、`AVG`、`MIN`、`MAX` | 對目前資料範圍的欄位／逐列運算彙總，也可使用逐列計算欄位。 |
| 文字 | `CONCAT`、`LEN`、`LEFT`、`RIGHT`、`MID`、`TRIM`、`UPPER`、`LOWER`、`SUBSTITUTE` | 文字組合、長度、擷取、修整、大小寫與文字替換。 |
| 日期與時間 | `DATE`、`TODAY`、`NOW`、`YEAR`、`MONTH`、`DAY`、`DATEADD`、`DATEDIFF`、`FORMAT_DATE` | 建立與拆解日期、日期加減、差值及格式化。 |
| 明確轉換 | `TO_NUMBER`、`TO_TEXT`、`TO_DATE`、`FORMAT_NUMBER` | 明確型別轉換與轉為顯示文字。轉換失敗應回報錯誤。 |

數值與日期的所有簽章、參數單位及邊界行為，須在該函式交付時一起完成目錄與測試。以上語法採接近 Excel 的形式，不承諾完整 Excel 相容性。

## 4. 語法與值

### 4.1 文字公式

沿用 `=` 開頭的公式，允許既有不含前導 `=` 的函式形式。支援數值、引號字串、`TRUE`／`FALSE`／`NULL`、括號、一元正負號、`+ - * /`、比較及函式呼叫。優先順序固定，MCP 目錄同時說明語法。

```text
=quantity * unitPrice
=IF(quantity > 0, ROUND(quantity * unitPrice, 2), 0)
=SUM(calc.lineAmount)
=CONCAT(params.customerName, "／", params.orderNo)
=DATEDIFF("day", params.startDate, params.endDate)
```

函式名稱不區分大小寫，欄位名稱保留來源的大小寫。字串、欄位與函式有明確區別；未知名稱應產生診斷。Label 的靜態文字不受影響。

建立自己的受限語法樹及求值器，不使用 JavaScript `eval`／`Function`。僅允許目錄中的語法與函式；物件路徑只解析資料自己的屬性。v1 不包含任意腳本、資料修改或外部 I/O。

### 4.2 型別、空值及短路

基礎值分為 number、string、boolean、date、datetime 及 null。明細陣列只透過資料範圍及彙總機制使用，不當作任意可執行物件。

- 已宣告的可空欄位缺值，或值為 JSON `null`，視為 null；引用不存在於欄位定義的名稱屬於未知欄位錯誤。
- `null` 參與一般算術或日期運算會傳遞為 null；顯示時可以留白，但不改寫為零。
- 型別不符不自動以 `Number(value) || 0` 修正。需要轉換時使用明確函式。
- `IF` 只求值被選取的分支；`COALESCE` 取得第一個非 null 的值後停止。`AND`／`OR` 的短路及可空布林語意須明列於目錄。
- 靜態驗證仍檢查各分支的語法、欄位名稱、函式與依賴。短路不會使不存在的函式或循環引用變成有效。

範例：`IF(quantity = 0, 0, amount / quantity)` 在 quantity 為零時回傳零，未選取分支不觸發除以零。

### 4.3 數值與顯示

以十進位運算規則處理報表數值；固定的精度／可表示範圍須列入引擎能力規格，超限回報診斷。實作時再選定符合體積預算的依賴，不在本文件指定套件。

`ROUND` 建議採半值遠離零，例如 `ROUND(1.25, 1) = 1.3`、`ROUND(-1.25, 1) = -1.3`；`ROUNDUP` 遠離零、`ROUNDDOWN` 朝零。這些都是明確的運算動作。

控制項的 `C0`、`N2`、百分比等格式只在呈現階段套用。兩筆 10.4 即使各自顯示 10，加總仍為 20.8；只有逐筆使用 `ROUND(value, 0)` 才得到 20。不得將已格式化字串餵回計算。

### 4.4 日期與時間

建議以 `YYYY-MM-DD` 表示純日期，datetime 使用含時區位移的 ISO 格式。純日期不因主機時區而變成前一天或後一天。模糊的在地日期字串交由明確解析規則處理，避免依作業系統猜測。

執行上下文固定一份 `executionTime` 與 `timeZone`。`NOW`、`TODAY` 在同一份報表中使用同一個時間快照；MCP 驗證及試算可傳入固定時間。時區由呼叫端指定，建議未指定時以 UTC 作可重現預設，保留在規格審閱時調整。

`DATEADD`／`DATEDIFF` 的單位為明確字串。月份加減遇到不存在的日期時，建議取目標月份最後一天；日曆天數差與經過的小時數分開定義。日期格式代碼須區分月份 `MM` 與分鐘 `mm`。

## 5. 計算欄位與作用域

### 5.1 建議結構

在 `ReportDefinition` 加入選填的 `calculatedFields`，既有範本沒有此欄位時仍有效。新欄位與公式設定需同步加入 TypeScript、JSON 驗證、Schema 編輯與 MCP。

```json
{
  "calculatedFields": [
    { "name": "lineAmount", "scope": "row", "type": "number", "expression": "=quantity * unitPrice" },
    { "name": "subtotal", "scope": "report", "type": "number", "expression": "=SUM(calc.lineAmount)" },
    { "name": "tax", "scope": "report", "type": "number", "expression": "=ROUND(calc.subtotal * params.taxRate, 0)" },
    { "name": "grandTotal", "scope": "report", "type": "number", "expression": "=calc.subtotal + calc.tax" }
  ]
}
```

上述只是 `ReportDefinition` 的新增部分，不是一份完整範本。計算欄位名稱在同一份報表內唯一；保留於獨立的 `calc` 命名空間，不覆寫傳入的原始 JSON。範例使用 `lineAmount`，避免與目前樣本中的原始 `amount` 欄位混淆。

### 5.2 可見範圍

| scope | 計算時機 | 可引用內容 |
| --- | --- | --- |
| row | 每筆明細一次 | 主檔參數、目前資料列、其他 row 計算欄位。 |
| group | 每組一次 | 主檔參數、同組 group 計算欄位、透過彙總取得目前群組的 row 值。 |
| report | 每份報表一次 | 主檔參數、其他 report 計算欄位、透過彙總取得全表 row 值。 |

v1 不開放會讓依賴範圍不明確的反向引用，例如逐列計算欄位直接依賴由自己加總產生的全表總計。合法性由作用域與依賴圖共同檢查，錯誤以可理解的欄位名稱回報。

控制項公式沿用所在 Band 的資料上下文。GroupHeader／GroupFooter 的預設彙總範圍是目前群組，ReportHeader／ReportFooter 是全表；Detail 仍可保留既有所在群組的彙總語意。MCP 需要能看到所在位置的有效範圍。

裸欄位名稱沿用既有「目前列 → 主檔參數」解析；新增明確的 `row.<field>`、`params.<field>`、`calc.<name>` 形式。若同名，設計器提示與 MCP 範例優先使用明確形式。

子報表的原始資料、計算欄位及彙總都在自己的報表範圍求值，主檔參數可以沿用。v1 不加入隱含的父報表計算欄位引用。

### 5.3 依賴及效能

先解析所有公式與名稱，再建立依賴圖、驗證作用域、找出循環並排序。循環診斷需顯示完整路徑，例如 `subtotal → tax → subtotal`。

編譯計畫可以依範本與函式目錄版本快取；運算值僅在單次執行、指定 row／group／report 內快取。傳入資料保持不變，頁面重排不重複計算，也不沿用其他資料批次的結果。

不將 PDF 分頁後才知道的 `[PageNumber]`／`[TotalPages]` 放入資料計算欄位依賴圖；它們仍是呈現階段的變數。既有 `=ROW_INDEX`／`=INDEX` 與頁碼文字樣板需保留相容路徑，並在目錄中區分一般函式與系統變數。

## 6. 驗證與錯誤

驗證分為結構、靜態語意及帶資料的執行三層。建議在正式儲存及 MCP 寫入時做結構／靜態檢查，失敗時保留原範本；文字編輯器則可保留尚未完成的輸入。通過驗證後的儲存立即生效，無須發布。

輸出 PDF 前，依實際資料完成運算驗證；任一錯誤阻止開始正式輸出，回傳診斷而非部分 PDF。前端可顯示編輯中的錯誤與預覽診斷，不能把上一次成功的預覽誤標成目前結果。

診斷結構至少包含：

```json
{
  "code": "DIVISION_BY_ZERO",
  "message": "計算欄位 unitAverage 的除數為零",
  "path": "calculatedFields[2].expression",
  "fieldName": "unitAverage",
  "scope": "report",
  "span": { "start": 1, "end": 30 }
}
```

依錯誤來源補充 bandId、controlId、subReportControlId、rowIndex、groupKey 與依賴路徑。建議錯誤類型涵蓋語法、未知函式／欄位、參數數量、型別、作用域、循環、除以零、日期無效與數值超限。

## 7. MCP 介面

| 工具／既有介面 | 建議行為 |
| --- | --- |
| `get_formula_catalog` | 回傳版本、語法、內建函式簽章、型別、範圍、空值／精度／日期規則、可執行範例及系統變數。可依類別或名稱篩選。 |
| `get_available_data_fields` | 保留原始欄位、主檔參數與範例；加入各作用域的計算欄位、型別及引用方式。函式建議改從共用註冊表產生。 |
| `validate_report_formulas` | 對指定或目前範本做靜態檢查；可搭配傳入資料做執行檢查，回傳依賴順序、有效範圍與結構化診斷。 |
| `preview_formula` | 在明確的範本、資料、scope 與 row／group 上試算單一公式，回傳原始結果、型別、可選的格式化文字及診斷。此工具不修改範本。 |
| `set_calculated_fields` | 原子替換指定主／子報表的計算欄位集合；靜態驗證失敗則整批不寫入，適合一次提交互相依賴的欄位。 |
| 既有控制項／整份範本更新 | 使用相同的結構及靜態公式驗證，不讓另一條寫入路徑繞過錯誤檢查。 |
| `export_pdf`／預覽輸出 | 依實際資料檢查公式，錯誤時回傳診斷，不輸出誤導性的檔案。 |

建議 Agent 流程為：查目錄及欄位 → 建立計算欄位與公式 → 驗證／試算 → 原子套用 → 產生預覽。所有入口共用同一套語法、求值與錯誤規則。

MCP 的能力發現屬 v1 必要驗收，不等到日後的獨立 AI 產品才補。測試不能只確認工具數量，還要確認目錄宣告的每個函式確實可執行、每個簽章有例子，並測試錯誤回應。

## 8. 設計器

新增計算欄位管理區：名稱、作用域、回傳型別、文字公式、驗證及試算結果。欄位選單同時呈現原始欄位與可見的計算欄位，並區分來源。

既有 Expression 編輯器提供函式／欄位插入、簽章說明、參數提示及即時診斷。選擇的函式說明直接來自共用目錄。回傳的診斷可定位到文字位置或計算欄位，並可用於修正後重新驗證。

保留目前控制項的格式設定。試算介面同時呈現「原始值」與「格式化結果」，讓管理人員能理解四捨五入只影響顯示。

第 1、2 階段的註冊表設計同時考慮 MCP，但不宣告未完成函式。第 4 階段完成後，才算達成可供 Agent 使用的能力交付。

示範資料用明確的稅率參數與計算欄位更新小計、稅額及總計。既有範例的固定中文大寫金額等文字也必須同步資料化或移除，避免與計算結果不一致。

保留目前 bundle 檢查：單一 chunk 不超過 500 kB、首頁靜態 JavaScript 不超過 650 kB，PDF 保持按需載入。引入解析或數值處理依賴時，驗證其是否被不必要地載入設計器首頁。

## 10. 驗收案例

| 案例 | 預期 |
| --- | --- |
| `2 + 3 * 4` 與 `(2 + 3) * 4` | 分別為 14 與 20。 |
| `0.1 + 0.2` | 十進位結果為 0.3。 |
| 兩筆 10.4，各自顯示 N0，再加總 | 原始小計為 20.8，不是 20。 |
| 兩筆 `ROUND(10.4, 0)` 再加總 | 原始小計為 20。 |
| `null * 5` 與 `COALESCE(null, 0) * 5` | 分別為 null 與 0。 |
| `IF(quantity = 0, 0, amount / quantity)`，quantity = 0 | 回傳 0，不執行除法分支。 |
| 平均 `[10, null, 20]` | 建議忽略 null，結果為 15。 |
| 空集合的彙總 | 建議 SUM／COUNT 為 0，AVG／MIN／MAX 為 null；目錄明列。 |
| `COUNT()` 與 `COUNT(field)` | 前者計列數，後者計非 null 的有效欄位值。 |
| 多個群組的相同彙總公式 | 各自只計算所在群組；全表計算欄位使用全部列。 |
| 子報表與主表有相同計算欄位名稱 | 各自在自己的資料範圍求值，結果不互相污染。 |
| a → b → a | 驗證指出循環與路徑，阻止儲存及輸出。 |
| 未知函式、未知欄位、錯誤型別或除以零 | 回報對應診斷，不輸出正式 PDF。 |
| 中文文字擷取及組合 | 不切斷 UTF-16 surrogate pair；字元索引與邊界規則列入目錄。 |
| 閏日、月底加月份、跨時區及同次多處 NOW | 結果符合固定日期規則，執行時間不在同份報表內漂移。 |
| Agent 只查 MCP 目錄及欄位後建立完整計算鏈 | 可驗證、試算、套用並成功輸出 PDF。 |
| 宣告的所有內建函式 | 每個目錄項目均有可通過的實際執行範例。 |
| 既有 SUM／COUNT／AVG、ROW_INDEX／INDEX 及頁碼樣板 | 相容案例持續通過；有意改變的空值語意明列於遷移說明。 |
